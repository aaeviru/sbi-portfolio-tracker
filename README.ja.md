# SBI Portfolio Tracker

[English](README.md) | [中文](README.zh.md) | [日本語](README.ja.md)

SBI証券のCSVファイルを取り込み、ポートフォリオの保有状況、実現/未実現損益、価格履歴、FX取引、金の保有状況を確認するためのローカルNode.js Webアプリです。

このアプリは個人分析用です。税務ソフトではなく、税務申告に関する判断や保証は行いません。

## 機能

- SBIの国内株式と投資信託の取引CSVを取り込み。
- SBIの米国株式の入出金・交割記録を取り込み。
- SBIの配当金・分配金CSVを取り込み。
- SBIのFX決済CSVを取り込み。
- SBIの金注文CSVを詳細な `GOLD_JPY` 取引行として取り込み。
- SQLiteにローカル保存。
- 株式と投資信託を同じダッシュボードで計算。
- FIFOで実現損益と残存コストを計算。
- 日本株、米国株、マッピング済み投資信託、金の最新価格を更新。
- 株式、投資信託、金の日次価格履歴を保存してチャート表示。
- 期待される市場営業日ごとに、完了、データなし、失敗、再試行待ちの価格履歴カバレッジを記録。
- 専用の価格更新ページで、進捗、ステータス絞り込み、銘柄別再試行、提供元日付、カバレッジ明細を表示。
- 米国株の円建て評価用にUSD/JPYレートを保存。
- 時価評価額、未実現損益、FIFO実現損益、配当/分配収入、合計実現損益、日次損益、構成比を含むポートフォリオサマリーを表示。
- ページング付きの取引一覧を表示。
- 保存済み価格履歴、売買マーカー、新しい順の売買履歴、テクニカル指標付きの取引チャートを表示。
- 月次/年次の合算サマリー履歴を、過去期間は履歴価格で計算し、Combined Total P/L差分と期間Detail明細を表示。
- ローカルSQLiteスナップショットから日次ポートフォリオレポートを作成。OpenAI APIで生成する方法と、英語・中国語・日本語のChatGPT貼り付け用プロンプトを使う方法に対応。
- ナビゲーションバーにアプリのバージョンを表示。

## ログイン

ポートフォリオ画面はシンプルなパスワードログインとHTTP-only JWT cookieで保護されます。通常の起動はフェイルクローズです。12文字以上の認証パスワードと、それとは独立した32文字以上のJWT署名シークレットを設定してください。

```powershell
$env:SBI_AUTH_PASSWORD = Read-Host "Enter the application password"
$env:SBI_JWT_SECRET = [Convert]::ToBase64String([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
npm start
```

既知のプレースホルダー値は拒否され、2つの値は同一にできません。起動エラーには無効な設定名だけが表示され、値は表示されません。

ローカル開発の場合に限り、ローカル専用モードを明示的に有効化できます。

```powershell
$env:SBI_LOCAL_ONLY="true"
npm start
```

ローカル専用モードは `127.0.0.1` のみにバインドし、パスワード未設定時は `admin`、JWTには独立した開発専用シークレットを使用します。インターネット公開環境では `SBI_LOCAL_ONLY` を有効にしないでください。

## J-Quants設定（任意）

日本株履歴の分割は、この連携を実装した時点の無料枠を前提にしています。J-Quantsは直近2年間のうち古い部分を取得し、Yahoo互換履歴は直近12週間と2年より古い日付を取得します。キーを画面へ表示せずに入力し、ユーザー環境変数へ保存すると同時に、現在のPowerShellセッションへ読み込んでから起動します。

```powershell
$secret = Read-Host "Enter your J-Quants API key" -AsSecureString
$key = [System.Net.NetworkCredential]::new("", $secret).Password
[Environment]::SetEnvironmentVariable("JQUANTS_API_KEY", $key, "User")
$env:JQUANTS_API_KEY = $key
Remove-Variable secret, key
Write-Host (-not [string]::IsNullOrWhiteSpace($env:JQUANTS_API_KEY))
npm start
```

確認結果は `True` である必要があります。キーはサーバーだけが読み取り、SQLite、ブラウザストレージ、Gitには保存しません。

キーがなくてもアプリは起動しますが、J-Quantsの担当範囲にある日本株の日付は、キーを設定するかSQLiteに既存データがあるまで失敗状態になります。

価格履歴更新の上限は任意で変更できます。

```powershell
$env:PRICE_HISTORY_MAX_REQUESTS="40"
$env:PRICE_HISTORY_MAX_DURATION_MS="600000"
```

この値は1回のUpdate All全体に適用されます。失敗区間と再試行時刻は保存されるため、後の実行で最初からやり直さずに続行できます。

- `/trade-chart` - 売買マーカーとテクニカル指標付きの価格履歴チャートを表示。

- `/daily-report` - 日次レポート用スナップショットを作成し、APIでレポート生成、または英語・中国語・日本語のChatGPTプロンプトをコピー。

## Daily Report

Daily ReportページはローカルSQLiteデータから小さなスナップショットを作成します。

- ポートフォリオ合計と保有中銘柄数
- 資産クラス別の構成比
- 主要保有銘柄と損益変動の大きい銘柄
- FXサマリー
- データ品質の警告

使い方は2つあります。

- `Generate today's report`: スナップショットをOpenAI Responses APIへ送り、Web検索を使ったMarkdownレポートを生成してSQLiteに保存します。
- `Use ChatGPT Chat Instead`: ChatGPTに貼り付けるためのプロンプトを英語・中国語・日本語でコピーできます。`OPENAI_API_KEY` は不要です。

ポートフォリオ数値はアプリがローカルで計算します。モデルは文章化と、現在の市場・ニュース背景との接続にだけ使います。

ChatGPTやDeep Researchを手動で使う場合は、JSONスナップショットを含む生成済みプロンプト全体を貼り付けてください。`@深度研究` のような短いトリガーだけを送ると、ポートフォリオレポートではなく一般的な調査計画テンプレートが返ることがあります。

## 取り込みメモ

インポーターは次のように正規化します。

- 日本株は `7974.T` のようなシンボル
- 米国株は `NVDA` のようなシンボル
- 投資信託はカスタムのファンドシンボル
- 金は `GOLD_JPY`

配当/分配CSVは、保有数量を変えない取引行として取り込みます。

- 株式収入は side `DIVIDEND`。
- 投資信託とMMF収入は side `DISTRIBUTION`。
- 収入行は数量やFIFOロットを変更しません。
- ポートフォリオの実現損益は、FIFO実現損益に配当/分配収入を加えた値です。

金CSVの取り込みでは集計メタデータを `gold_holdings` に保存し、約定済みの各金注文も通常の `transactions` テーブルへ取り込みます。詳細な取引行は、サマリーのFIFO、取引チャートの買付マーカー、金価格履歴の更新に使われます。旧式の手動金入力フォームは削除済みです。

SBI CSVには正確な約定時刻がなく、日付のみの場合があります。アプリは安定した並び順のために次の合成時刻を割り当てます。

- BUY は `09:00:00`
- SELL は `15:00:00`

これにより、同日売買のFIFO処理を安定させます。

## 価格更新

`/prices` で `Update All` を押します。更新はバックグラウンドで実行され、ページは `/prices/status` を定期確認して進捗を表示します。銘柄別の `Retry` は同じ処理をその銘柄だけに実行し、現在の再試行待ち時間を一度無視します。

現在の動作：

- ネット数量がゼロの資産はスキップ。
- Yahoo互換のチャートデータから株式の最新価格を取得。
- 日本株履歴は、直近12週間をYahoo、直近2年内の古い部分をJ-Quants、2年より古い部分をYahooアーカイブから取得。
- 履歴開始日は、保有中の株式、投資信託、金ごとに「2年前」と「最古BUY日」のうち古い方。
- 投資信託はマッピングURL/コードが保存されている場合のみ価格を取得。
- 金価格を取得して円/グラムへ変換。
- 外貨MMFはSBI取引CSVの価格を使用し、市場履歴プロバイダーへは送信しない。
- 株式の日次OHLC価格履歴を保存。
- マッピング済み投資信託のNAV履歴を保存。チャート用には1万口あたりで保存し、サマリー評価では単価へ戻します。
- `GC=F` 金先物と `JPY=X` USD/JPYを組み合わせ、各日付の金価格を円/グラムとして保存。
- 最新価格の取得に成功したものの、日次履歴エンドポイントにまだ行がない場合は最新価格スナップショットを保存。
- ライブ価格スナップショットは、完了済みの日次市場履歴としては扱わない。
- 区間カバレッジを `COMPLETE`、`NO_DATA`、`FAILED` として保存。取得済み行と上場前などの有効なデータなし日付は再取得しない。
- 欠損区間を新しい順に取得。デフォルトでは、1回の実行で全資産合計40履歴リクエスト、最大10分。
- 失敗日付は1時間から24時間の指数バックオフで延期し、レート制限は15分待機。銘柄別Retryでは一度だけ待機を無視。
- J-Quants無料枠向けにリクエスト間隔を12.5秒に調整。
- 提供元ごとに区間サイズを制限し、資産間に短い遅延を入れ、レート制限で必要な場合は残りの処理を停止。

「今日」に相当する履歴終端日は資産ごとに異なります。

- 日本株は完了済みの最新東京市場日。
- 米国株と金は完了済みの最新ニューヨーク市場日。
- 投資信託は判明している最新の基準価額公表日。
- MMFはSBI取引CSVから取り込んだ価格日。

期待される履歴日から、週末と既知の日本・米国市場休場日を除外します。Price Update表には、提供元価格日、完了履歴範囲、ライブスナップショット日、未取得営業日数、次回再試行、保存済みカバレッジ区間が表示されます。

米国株では、必要に応じてチャート比較日を米国市場日へずらします。一方、元のSBI取引日は表に表示され続けます。

日次損益は、現在の円建て時価評価額と前回保存済みの価格履歴日を比較します。これにより、週末、休場日、投資信託NAVの遅延による不自然な空白を避けます。

## 合算サマリー履歴

`/history` はローカルの現在日付までで当月と当年を計算するため、現在行はライブのCombined Summaryと一致する想定です。過去の月次/年次行は期間末時点のカットオフで、各期間末日以前の最新保存価格履歴を使用します。履歴価格がない場合のみ、現在の資産価格にフォールバックします。

月次または年次行の `Detail` を開くと、その期間の変化理由を確認できます。明細ページは選択期間末と前期間末を比較し、次を表示します。

- Combined Total P/L変化の主な資産要因とFX要因
- 資産ごとの時価評価額、未実現損益、実現損益、収入、合計損益の変化
- その期間内のポートフォリオ取引
- その期間内のFX取引

## データソースに関する注意

直近の株式と金の価格履歴はYahoo互換のチャートデータを使用します。古い日本株履歴は `JQUANTS_API_KEY` が設定されている場合に公式J-Quants APIを使用します。金の円/グラム履歴はUSD/JPYチャートデータにも依存します。投資信託の価格履歴は、Yahoo Japanフロントエンドのファンド履歴エンドポイントと短期ページトークンを使用します。このファンドエンドポイントは公式公開APIではないため、ローカル個人利用向けのベストエフォートとして扱ってください。

Yahooがトークン、エンドポイント、レスポンス形式を変更した場合、履歴のバックフィルは失敗する可能性があります。アプリは明確な取得エラーを表示し、最新価格スナップショットをフォールバックとして使えます。

## 取引チャート

取引チャートは次の範囲を表示できます。

- 1か月
- 6か月
- 1年
- 全期間

X軸ラベルは週次、月次、年次にできます。全期間より短い範囲では、Previous/Nextで表示ウィンドウを移動できます。

売買履歴テーブルはBUY/SELLを新しい順で表示します。

利用できるテクニカル指標：

- SMA 20、SMA 50、SMA 200
- Bollinger Bands 20/2
- 30/70基準線付きRSI 14
- シグナル線とヒストグラム付きMACD 12/26/9
- 20日年率実現ボラティリティ、52週高値/安値、ドローダウンの要約値

指標は保存済みの日次終値からローカル計算します。完了済み日次履歴が不足している指標は表示されません。MMFは安定した取込NAVから有用なシグナルを得にくいため対象外です。
